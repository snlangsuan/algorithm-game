# เทสต์

```bash
npm test
```

ตัวรัน (`run.mjs`) bundle ไฟล์ `*.test.ts` ด้วย esbuild ที่ติดมากับ vite แล้วส่งให้ `node --test`
จึงไม่มี test framework เพิ่มใน dependencies และเขียนเทสต์ด้วย alias `~` ได้เหมือนโค้ดในแอป

## ครอบอะไรอยู่

| ไฟล์ | ตรวจอะไร |
|---|---|
| `roundtrip.test.ts` | บล็อก→โค้ด→บล็อก→โค้ด ได้โค้ดเดิมเป๊ะ, ไม่เหลือบล็อก "โค้ดของฉัน", จำนวนบล็อกเท่าเดิม, `lineOf`/`blockOf` เป็นคู่ผกผัน, บล็อกทุกตัวลงทะเบียนแล้ว, บล็อกทุกตัวในกล่องเครื่องมือ (ไม่ใช่แค่ตัวที่ตัวอย่างใช้) อ่านกลับเป็นบล็อกเดิมได้, `normalize` เติมช่องครบทุกหัว, ชื่อ/ลำดับหมวดเป็นของระบบ, บล็อกความจำโผล่เฉพาะเกมที่รองรับ |
| `learning.test.ts` | ตัวอย่าง "วิวัฒนาการ" ใช้บล็อกความจำจริง และซ้อมแล้วชนะ "ยึดมุมก่อน" บ่อยขึ้นจริง |
| `preset-lock.test.ts` | ตัวอย่างสำเร็จรูปแก้ไม่ได้ · คัดลอกแล้วปลดล็อกและแก้ได้ · เลือกตัวอย่างอื่นกลับมาล็อกอีก |
| `knowledge.test.ts` | หน้า `/learn` อ้างถึงของจริง — ตัวอย่างที่ชี้ไปยังมีอยู่, ไฟล์ต้นทางยังอยู่, บล็อกอธิบายสร้างได้, อ้างอิงทุกอันมีปี |
| `hanoi.test.ts` | ตัวอย่างของหอคอยฮานอยย้ายถูกกติกาและได้ 2^n − 1 ตาซึ่งน้อยที่สุดเท่าที่เป็นไปได้ · แบ่งแล้วพิชิตได้ลำดับเดียวกับเฉลยของเอนจิน · กฎสลับตาได้จำนวนตาเท่ากันโดยไม่วางแผนล่วงหน้า · ตัวอย่าง "เริ่มต้น" ยังแก้ไม่ได้ตามที่ตั้งใจ |
| `chase.test.ts` | สนามไล่จับทุกสนามเดินถึงกันหมดและวางของไว้บนพื้นจริง · ทางที่สั้นที่สุดเดินได้ทีละช่อง · กติกาคนหนีทั้งโหมดคนเล่นและโหมด AI (ชนกำแพง เก็บของ ประตูเปิดเมื่อของครบ เดินสวนกันนับว่าโดนจับ และจดว่าตัวไหนจับ) · ผู้ไล่ล่ายืนทับกันไม่ได้ทั้งรอบ และบล็อก "ไม่เบียดเพื่อน" เลี่ยงทางที่เพื่อนอยู่จริง · ผู้ไล่ล่าเดินช้าตามความเร็วที่ตั้งไว้ · ตัวอย่างของทั้งสองฝ่ายทำงานตามที่โฆษณาไว้ · เล่นทั้งรอบแล้วยังชนะได้ เพิ่มผู้ไล่ล่าแล้วยากขึ้นจริง และ AI ฝ่ายหนีที่รู้จักหลบอยู่รอดนานกว่าตัวที่เก็บของอย่างเดียว · ตัวเลขในหน้าความรู้ของฝ่ายหนีกับภาพประกอบ มาจากการเล่นด้วยบล็อกจริง |
| `game-previews.test.ts` | ภาพย่อในรายการ "เลือกเกม" คงที่ทุกครั้ง · เส้นทางในภาพเดินได้จริง · กระดาน Othello ในภาพถูกกติกา |

ทั้งหมดรันใน Node ล้วน ไม่ต้องเปิดเบราว์เซอร์และไม่ใช้ Web Worker

## ข้อควรรู้

- **เทสต์ GA ล็อกเลขสุ่มไว้** (`SEED` ใน `learning.test.ts`) เพราะ GA สั่นมาก
  ถ้าไม่ล็อกและใช้ 6 รอบ จะตกประมาณ 1 ใน 5 ครั้ง ตอนนี้ใช้ 40 รอบ + seed ตายตัว ผลจึงเท่าเดิมทุกครั้ง
  ถ้าแก้โค้ดแล้วเทสต์นี้ตก แปลว่าความสามารถในการเรียนรู้แย่ลงจริง ไม่ใช่ดวง
- **ห้ามเช็ค "โปรแกรมนี้เรียนรู้ได้ไหม" ด้วยการ scan โค้ดที่แปลงแล้ว** — `CORE_HELPERS`
  ที่ระบบเติมให้ทุกโปรแกรมมีคำว่า `saveMemory(` อยู่ ใช้ `usesBlock(program, [...])` แทน
- **ห้ามเปลี่ยน fitness ของ GA กลับไปใช้แพ้/ชนะ** เคยลองแล้วแย่ลงชัดเจน
  (สัญญาณ 1 บิตต่อเกมหยาบเกินไป แชมป์ถูกแทนด้วยตัวที่ชนะฟลุก)
- **`nuxt-shim.ts` ถูก inject เข้าไปตอน bundle** เพราะ `ref`/`reactive`/`computed` เป็น auto-import ของ Nuxt
  ถ้าเทสต์ฟ้องว่า `ref is not defined` แปลว่ามีชื่อใหม่ที่ต้องเติมในไฟล์นั้น
- **ชื่อในดรอปดาวน์ (`preset.name`) กับชื่อโปรแกรม (`preset.build().name`) เป็นคนละตัว** อย่าเอามาเทียบกัน

## ยังไม่ได้ครอบ

ส่วนที่ต้องมี DOM จริงยังไม่มีเทสต์ในโปรเจกต์ ต้องไล่ด้วยมือหรือด้วย CDP:
ลากวางบล็อก, รูรับเฉพาะชนิดที่ตรง, เดือย/ร่องทับกันพอดี, คอนโซลในหน้าเกม, สลับโหมดบล็อก↔เขียนโค้ดเอง

**ห้ามทดสอบ drag ด้วย `new DragEvent()` ใน JS** — ผ่านตลอดทั้งที่ผู้ใช้ลากจริงแล้ววางไม่ได้
ต้องใช้ CDP `Input.setInterceptDrags` + `Input.dispatchDragEvent` เท่านั้น และเริ่มลากได้ครั้งเดียวต่อหน้า
